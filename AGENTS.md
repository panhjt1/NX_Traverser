# Repository working instructions

- Target runtime: Windows x64, Siemens NX 2512 / Teamcenter integration. The default compilation target is .NET Framework 4.8; an explicit v4.7.2 compatibility build is available for the user's existing project. Keep NX 2512 references and framework compatibility diagnostics; the target setting does not change the NX host runtime or prove compatibility.
- After every source, DLX, or build configuration change, update `LOCAL_AGENT_PROMPT.md` with what changed, validation performed, and remaining local-agent tasks. Keep `docs/NX2512_API_REVIEW.md` current when API assumptions change.
- The user's browser and local build-agent networks are isolated. Push the branch and maintain `LOCAL_AGENT_PROMPT.md`; report the commit without download links. The user downloads the ZIP from GitHub. Do not require local Git network access or a `.git` directory. Preserve local edits when replacing snapshots.
- Verify NX API names/signatures against the official target-version reference or installed SDK. Do not invent dialog suppression APIs or use reflection to guess them.
- Do not save, check out, change access permissions, or clear modified flags on users' source parts. The user explicitly requests timely unloading: individually close this run's temporary parts, including initially clean partial/minimal parts touched/promoted by the run, without saving. Protect initially fully loaded/modified parts, original displayed/work parts and work-occurrence ancestors, and active traversal ancestors. Never close an entire tree or all parts. Stop on failed cleanup. Restore work/display/view context before unloading; do not promise restoration of NX undo history or complete suppression of native/site dialogs.
- Keep Siemens SDK binaries, signing resources, licenses, and company model data out of this repository. Reference the local NX installation with Copy Local=false.
- Preserve DLX block IDs. Generate Styler template code separately; `UIscripts.cs` is maintained manually.
- Preserve screenshot features: hide WCS and view triad using view-local flags, then restore the exact original values on success/error/cancel. The user rejected isolate views because they accumulate windows and add a green border/number to images. Do not create isolate views or add layout-exit experiments. The user now requests showing only the selected occurrence within the original assembly. Keep work/display unchanged for screenshots, mask other occurrences temporarily and restore exact blank states before unloading; compensate camera rotation for the target prototype ACS. Never activate a prototype as an image fallback. Measurements share the original-assembly export context with screenshots: use displayed occurrence bodies (exclude hidden/suppressed/refset-excluded geometry and invisible layers), query exact bounds in a temporary transformed target ACS/WCS, and never activate or explicitly fully load a prototype as a fallback. Hide auxiliary objects for screenshots and restore their exact prior blank states. Stop and preserve the loaded set if context restoration fails. Rendering and native dialogs require local NX validation; test doubles do not establish native behavior.
- Run checks relevant to a change. Existing independent checks: `python tests/validate_dlx.py` and `dotnet run --project tests/CoreTests.csproj -c Release`. NX compilation and integration validation require the local Windows agent; state precisely which checks actually ran.
- Model auxiliary objects (reference CSYS, points, sketches, datums, etc.) must only be blanked/unblanked and restored, never deleted. Measurement may create its own non-displayed/non-filed CSYS via CoordinateSystems.CreateCoordinateSystem(Point3d, Matrix3x3, true) and release only that returned object. Do not create or delete an explicit NXMatrix tag, infer exclusive ownership from a creation API name, or treat an NX-managed matrix's Condemned status as failed cleanup. Keep cleanup checks for the actual self-created CSYS.

- Cancellation is task-wide and latched for the current run. The independent stop window may only set the managed stop flag from its own UI thread; all NX calls and logs remain on the NX thread. Poll documented UFAbort.AskFlagStatus at work checkpoints; acknowledge only observed/handled native aborts. Do not assume NX retains an already-consumed abort flag, guess cancel error codes, disable abort globally, or interrupt cleanup. Restoration, temporary-object deletion and per-node unloading must run after stop. Join the stop-window thread before immediate plugin unload; retain until termination if it remains alive.

- Preserve the main traversal loop + standardized pluggable transactions architecture. Default handlers are composed only in BuildTransactionHandlers; explicit Run(config, transactions) permits extensions without modifying recursion. Handlers implement only Process(TransactionContext) and Finish. The driver owns context creation/closure, per-transaction frame restoration, error/cancellation policy, counting, source-part unloading, and exactly-once per-run Finish after accepting the list (including startup failure). Constructors validate options only. Transactions borrow context/NX objects; never cache them across targets or manage source-part lifetimes. Shared view/load/measurement code belongs in existing services, not duplicated in handlers. RunLog records observations; TraversalCancellation owns execution/cancellation policy. Keep metadata-only transactions independent of image-view preparation.
